# The Big 12 mechanical buckets — design

**Date:** 2026-09-16
**Status:** awaiting Cole's review

## What this is

OnBaseU's Big 12: the twelve inefficiencies Cole looks for in a pitcher's delivery.
The app already holds the other half of the OnBaseU model, the physical movement
screen, as 16 tests across core, rotation, stride, posture and arms.

The point of putting the twelve in the app is not to store twelve checkboxes. It is
that OnBaseU's whole method says a physical limitation EXPLAINS a mechanical flaw,
and the screen findings that would explain a flaw are already on the same record.
Cole reads across the two by hand today.

## Decisions

| Decision | Choice | Why |
|---|---|---|
| What is recorded | Present or not | Cole's call. A flaw is something he saw or did not. |
| When | On the movement screen record | He assesses the delivery at the same session as the screen. No new page, no new cadence. |
| Who records | Coach only | Same rule the screen already enforces server-side. Athletes read their own. |
| Mapping grain | Test level | A flaw names screen TESTS, not individual findings. Finding-level would be a far longer list for Cole to supply and can be sharpened later. |
| Several causes | Ranked, lead one shown | Some flaws touch 10 of 16 tests. A flat list would print five explanations every time, which is the same as saying nothing. OnBaseU's own text ranks them, usually with the word "Foremost". |
| Sides | Derived from throwing hand | Causes are written per side ("backside hip", "front side hip flexion"). Showing a limitation in the wrong leg is worse than showing nothing. |
| Flaw to flaw | Supported | Cole's source names Short Stride as a cause of Flying Open, and Early Release's causes are ENTIRELY other flaws. Without this, Early Release explains nothing ever. |
| Strength | Not linked | Leg strength and power is named in 6 of the 12 and has no screen test. Cole's decision, made once and confirmed after seeing the count: the strength page is a click away. |
| Closing the back side | Not recorded | Cole: a backside close is not a fault unless it is extreme. An extreme one goes in the screen's notes. |

## Data

A `flaws` column on `movement_screens`, additive and idempotent, same as every
migration in this app. `SCHEMA_VERSION` goes to 26, so this needs a `/api/setup` run.

Shape: an object keyed by flaw key, values `true`. Absent means not seen. There is no
false, because "not seen" and "not assessed" are the same statement from a coach who
watched the delivery.

## Config: `lib/big12.ts`

```ts
interface Cause {
  label: string;              // Cole's own wording, shown as the report heading
  tests: string[];            // SCREEN_TESTS keys, may be empty
  side?: "front" | "back" | "throwing";
}

interface Flaw {
  key: string;                // reaches the database, never changes
  label: string;              // freely reworded
  description: string;        // what it is, in Cole's voice
  howToSpot: string;          // the video-analysis procedure
  causes: Cause[];            // RANKED: index 0 is what OnBaseU calls foremost
  causedBy?: string[];        // other flaw keys, ranked
}
```

`side` resolves against the athlete's throwing hand: a right-hander's front leg is the
left. With no hand recorded there is no front leg to work out, so both sides show.

A cause with an empty `tests` list is kept, not dropped. It is a cause OnBaseU names
that this screen cannot measure, and the config is the honest record of that.

## The twelve

Ranked. `[back]`, `[front]` and `[throwing]` mark side-resolved causes.

**Sway** — hip rotation `[back]`: hip-45, toe-tap / ankle eversion `[back]`:
ankle-rolling / spine disassociation: pelvic-rotation, seated-trunk-rotation / lower
body stability: side-step-walkout, half-kneeling / hip flexion `[front]`: none

**Hanging Back** — hip mobility and stability: hip-45, toe-tap / spine disassociation:
pelvic-rotation, seated-trunk-rotation / ankle eversion `[back]`: ankle-rolling / leg
strength and power: none / hip flexion `[front]`: none

**Closing the Front Side** — spine and hip mobility: hip-45, pelvic-tilt, wide-squat,
lunge-extension / spine disassociation: pelvic-rotation, seated-trunk-rotation / hip
and core stability: half-kneeling, side-step-walkout, toe-tap, wide-squat / ankle
plantarflexion: heel-lift / shoulder mobility: lunge-extension

**Getting Out In Front** — spine disassociation: pelvic-rotation,
seated-trunk-rotation / thorax mobility and spine extension: lunge-extension,
seated-trunk-rotation / hip mobility and stability: hip-45, toe-tap / leg strength and
power: none

**Late Riser** — shoulder external rotation `[throwing]`: shoulder-90-90 / spine
disassociation: pelvic-rotation, seated-trunk-rotation / spine extension:
lunge-extension / scapular stability: none

**Flying Open** — spine disassociation: pelvic-rotation, seated-trunk-rotation /
thorax mobility: seated-trunk-rotation, lunge-extension / hip mobility and stability:
hip-45, toe-tap / shoulder mobility and stability: none / leg strength and power: none
/ caused by: short-stride

**Early Extension** — hip mobility and stability `[back]`: hip-45, toe-tap / ankle
eversion `[back]`: ankle-rolling / spine disassociation: pelvic-rotation,
seated-trunk-rotation / leg strength and power: none / hip flexion `[front]`: none

**Short Stride** — hip mobility: hip-45, toe-tap, wide-squat, lunge-extension / spine
extension: lunge-extension / ankle plantarflexion: heel-lift, push-off / ankle
eversion: ankle-rolling, push-off / lower limb reciprocal pattern: lunge-extension,
half-kneeling / balance: heel-lift, half-kneeling / core and lower body stability:
half-kneeling, side-step-walkout, wide-squat, toe-tap / leg strength and power: none

**Collapsing Front Knee** — hip internal rotation `[front]`: hip-45, toe-tap / lower
body stability: half-kneeling, side-step-walkout, wide-squat, toe-tap / tibia
rotation: none / ankle mobility `[front]`: heel-lift, ankle-rocking, ankle-rolling /
balance `[front]`: heel-lift, half-kneeling

**High Hand** — shoulder external rotation `[throwing]`: shoulder-90-90 / spine extension:
lunge-extension / leg strength and power: none / elbow mobility and stability `[throwing]`:
forearm-80-80 / scapular stability: none

**Early Flexion** — spine extension: pelvic-tilt, lunge-extension / hip flexion
`[front]`: none / lower limb reciprocal pattern: lunge-extension, half-kneeling /
spine disassociation: pelvic-rotation, seated-trunk-rotation

**Early Release** — no physical causes / caused by: short-stride, high-hand,
early-extension

Cole's source adds "by product of many of the other inhibitors" to Early Release. That
is deliberately NOT expanded into eleven links: every marked flaw would print under it
and the report would say nothing. It lives in the description instead.

## What the screen cannot answer

Kept here because it is a finding about the screen, not a gap in this feature.

| Cause | Entries naming it |
|---|---|
| Leg strength and power | 6 of 12 |
| Front-side hip flexion | 4 of 12 |
| Back scapular stability | 3 of 12 |
| Shoulder abduction, tibia rotation, ankle dorsiflexion | 1 each |

Front-side hip flexion is the one worth revisiting: on Early Flexion, Cole's source
ties that compensation to disc and lower back injuries, so the silence there costs
more than an explanation. Closing it means adding a test to the screen, which is
Cole's to specify and out of scope here.

Windshield Wiper is named by none of the twelve. Shoulder internal rotation is not a
cause in any entry. Left alone, noted so it is not read as an omission.

## What counts as an explanation

"Test level" needs a precise rule, because the screen's own config says three kinds of
answer are not deviations and must not be read as failures.

A mapped test explains a flaw when it has at least one finding that is ALL of:

- on a sub-test that is not `diagnostic`. Those record context rather than grade
  anything, and the screen's config says in as many words that they must not be
  counted as deviations. Push-Off's "Where was this tested?" is one: on the mound
  versus on flat ground is not a limitation.
- not `normal: true`.
- not `NOT_TESTED`. A skipped sub-test is an absence, not a finding.

A `PAINFUL` finding counts, and carries its alert through to the report rather than
being flattened into the explanation. Pain is off the scale, which is how the screen
and the recovery check-in both already treat it.

Severity is not used for this. It is optional throughout the screen config, unset
until OnBaseU's mapping is supplied, and a rule that leaned on it would go quiet on
every test that has no colours yet.

## Recording

A section below the physical tests in `ScreenModal`, twelve checkboxes in Cole's
order, each with its description and how-to-spot text available while grading. Coach
only, enforced in the route rather than hidden in the UI.

## The report

In `ScreenPanel`, under each flaw marked present:

- The highest-ranked cause with an abnormal finding, named by Cole's own cause
  wording, with the finding and its side.
- Remaining causes with abnormal findings behind a "more" line.
- Other flaws marked on the same record that this one lists in `causedBy`.
- When nothing explains it: said plainly. A pitcher who sways because his stance is
  too wide will screen clean, and that is the common case, not an edge case. A report
  that only listed matches would make him look identical to an athlete nobody screened.

## Testing

- Every test key in every `causes[].tests` exists in `SCREEN_TESTS`. A renamed or
  mistyped key would explain nothing, silently, forever. This app has shipped that
  shape of bug before.
- Every key in `causedBy` is a real flaw key, and no flaw lists itself.
- Twelve entries, unique keys, Cole's order.
- The API rejects a flaw key it does not recognise.
- An existing screen row with no `flaws` value survives the migration and reads back
  as no flaws. This is the upgrade path, and it is the bug this app has shipped twice.
- Side resolution: a right-hander's front leg is the left, a left-hander's is the
  right, and an athlete with no hand recorded gets both.
- A test serving two causes is listed once, at its highest rank.
- A diagnostic sub-test never counts as an explanation. Push-Off recorded on flat
  ground must not make Short Stride look explained.
- A skipped sub-test never counts as an explanation.
- A painful finding counts, and reaches the report as an alert rather than as a
  plain explanation.
- A flaw with every cause unmapped reports as unexplained rather than crashing.

## Out of scope

Strength links, a Closing the Back Side checkbox, new screen tests for the gaps above,
and any finding-level mapping.
